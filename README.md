# magpie-remote

为 **Magpie** 提供 SSH 连接管理、双向 TCP 端口转发和远程 Magpie 生命周期管理。

在 Magpie 侧栏的 **SSH 连接** 页面中，可管理服务器、连接和断开，以及保存、启动、停止和删除 c2s / s2c 端口转发。「远程 Magpie」面板可检测 Linux 环境，预览并执行安装、更新、用户服务启停和保留配置的卸载，通过 SSH 转发访问官方 Web 管理供应商与 Agent。

本插件是供用户操作的管理页面。页面需要的 SSH 和远程管理后台随插件启动，不向 Magpie 注册 MCP 工具或模型供应商。升级自旧版本后，原有连接配置保留；此前通过 MCP 调用本插件的方式不再可用，请在页面中操作。部分 Magpie 版本可能因为插件带有后台入口而显示「供应商」标签，详见[开发说明](docs/development.md)。

插件卡片、侧栏和页面复用同一个支持明暗主题的 SVG Logo。`magpie.icon` 内嵌图标供插件卡片读取，`magpie.page.icon` 指向包内的 `page/icon.svg`。替换原始 PNG Logo 后运行 `npm run icons` 同步生成两处配置。

安装或重新加载插件后，在侧栏打开「SSH 连接」，新增服务器并选择登录方式。选择「密码」可直接输入密码，点击「保存并连接」后登录；密码以 AES-256-GCM 密文写入配置，本机随机密钥单独保存。其他方式先尝试已有认证来源，需要时提示输入本次凭据；本次凭据不保存。已连接时可创建并启动转发，未连接时保存预设；预设按连接的自动启动设置运行，也可选择个别预设失败时保留连接并继续启动其他规则。

Windows 桌面内嵌页面的来源为 `http://wails.localhost`，v0.2.1 已将它加入允许嵌入的来源名单，修复服务正在运行时仍显示「127.0.0.1 拒绝连接」的问题。升级后在「设置 → 插件」中关闭再开启本插件，让插件宿主重新读取代码。

管理服务随插件启动，只监听本机随机回环端口。启动页在当前 Magpie iframe 内导航到该服务；服务使用独立随机访问标识和 API 认证，共用现有 SSH 后端。`webUI: false` 可关闭页面服务，`uiPort` 可指定端口。插件目录需允许写入 `page/.runtime/`，其内容不进入 Git 或 npm 包。

| 功能 | 行为 |
| --- | --- |
| 连接管理 | 新建、编辑、搜索、状态筛选、重连和删除；支持多个独立会话 |
| SSH 配置导入 | 页面预览和勾选导入，支持 Include；已有连接跳过，导入后不自动连接 |
| SSH 认证 | 加密保存的密码、私钥文件、SSH agent，或通过环境变量提供密码与私钥口令 |
| c2s / `-L` | 在客户端监听，把流量通过 SSH 发往服务器侧目标 |
| s2c / `-R` | 在服务器监听，把流量通过 SSH 发往客户端侧目标 |
| SSH 生命周期 | 认证完成才算已连接；可单独停止转发；断线时释放资源 |
| 远程 Magpie | Linux 用户安装、更新、服务启停、启用 Web 与卸载；变更先预览，按当前命令能力管理，更新先备份 |
| 供应商与 Agent | 建立临时回环 SSH 转发，访问远端官方 Web 管理；插件内嵌编辑界面尚未加入 |
| 远端任务 | 保存每连接最新操作，页面刷新后继续查看；断线结果待核实，禁止自动重放 |
| 自动重连 | 按连接启用；仅网络故障退避重试，手动停止即取消；认证和公钥问题暂停等待处理 |
| 配置备份恢复 | 保存前自动备份，保留最近 5 份；支持手动备份、预览恢复和损坏配置恢复 |
| 持久化 | 保存连接配置和预设转发；运行中的会话保留在宿主内存中 |
| 运行日志 | 查看认证、断线、转发启停和错误；每个连接保留最近 200 条内存日志 |

## 安装和接入

开发需要 Node.js 22 或更高版本。Magpie 使用自己的 Bun 运行插件，代码无需构建。依赖 `ssh2` 使用纯 JavaScript 路径，不依赖安装脚本或原生扩展。

在 PowerShell 7 中进入项目目录：

```powershell
npm ci --ignore-scripts --omit=optional
npm run check
npm test
magpie plugin add .
```

也可以在 Magpie 的「设置 → 插件 → 添加插件」中填写项目文件夹的绝对路径。文件夹安装会直接加载源文件。

安装后启用插件，在 Magpie 侧栏打开「SSH 连接」。升级已有安装时，关闭再开启插件以加载新版本。

## 使用示例

1. 点击「新建 SSH 连接」，填写服务器地址、用户名和认证方式，再保存并连接。首次连接时按提示核对服务器主机公钥。
2. 在连接详情中新建 c2s 转发，设置本地监听端口 `18080` 和服务器侧目标 `127.0.0.1:8080`，可从本机访问远端服务。
3. 如需从服务器访问本机服务，新建 s2c 转发，设置远端监听端口 `13425` 和本机目标 `127.0.0.1:3425`。服务器应用可通过 `127.0.0.1:13425` 访问本机 Magpie 网关，仍需提供网关要求的认证信息。
4. 需要下次连接时再次使用的转发，创建时勾选「保存为预设」。操作完成后可停止单条转发，或断开连接以释放全部转发。

已支持断网自动重连和配置备份恢复。自动重连默认关闭，在连接编辑器中按需开启；页面顶部「备份与恢复」提供手动备份与预览恢复。恢复会停止全部连接并保留原配置，完成后按需手动连接。

远程任务保留当前记录与最近 20 条终态历史，可在运行日志中筛选，也可按操作 ID 查询。明确尚未派发的任务在宿主重启后结束为本地中止；可能已经执行的任务继续等待核实，不自动重放。页面同时显示非阻断的备份清理警告，以及认证、主机信任与 agent 的修复引导。

远程管理首版支持普通 Linux amd64/arm64 的用户安装，供应商和 Agent 通过转发后的官方 Web 管理，插件内嵌编辑留待后续。备份、更新与恢复统一保存未加密的配置归档和当前程序副本；归档可能包含密钥，请妥善保管。恢复结果分别报告配置、服务、回退与恢复依据，应用后启动失败不自动回退。断线或超时结果保持待核实。使用范围与操作流程见[远程 Magpie 管理](docs/remote.md)。

`npm run check:release` 统一运行静态、Node、隔离 POSIX 脚本、两套 iframe 页面、可用的 Bun 与显式提供的实际宿主检查，并生成含包文件清单的 `.local/release-check.json`。缺少外部验收时明确标为 `not_run`；`npm run check:release:strict` 要求全部通过。Ubuntu/Windows × Node 22/24 的 CI 已配置，真实 Linux 生命周期有[专用账户验收入口](docs/linux-acceptance.md)。本机回归使用临时配置、回环 SSH 与受控响应，未替代真实 Linux/systemd 验收；结果见[验证记录](docs/verification.md)。
