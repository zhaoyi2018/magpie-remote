# 远程 Magpie 管理

连接 SSH 后，在「远程 Magpie」页检测当前登录用户的环境。首版支持普通 Linux amd64/arm64 的用户安装：安装、更新、用户服务启停、启用官方管理页面和保留配置的卸载。供应商与 Agent 通过官方管理页面操作；插件内的独立编辑界面尚未加入。

## 使用流程

1. 建立 SSH 连接，打开「远程 Magpie」，点击检测环境。SSH 已连接与 Magpie 正在运行是独立状态。
2. 未安装时预览安装。本机后台从官方 `https://usemagpie.ai/api/latest` 读取远端 Linux 架构对应的 CLI 资产 URL 和 SHA-256，支持 `https://usemagpie.ai/files/` 与官方 GitHub 发布仓库。确认后在运行插件的本机下载并校验，通过已连接的 SSH 上传，远端再次校验后安装到 `~/.local/bin/magpie`。服务器无需访问互联网或安装 curl；本步骤不启动服务。
3. 已安装程序但尚无用户服务时，先点击「启用 Web」，预览后创建并启动当前用户的 systemd 服务，再使用服务启停按钮。网关使用回环地址，管理页面使用 `127.0.0.1:3430`。无 systemd 用户会话时保留程序安装，服务操作会明确拒绝。
4. 获取管理链接。后台显式读取 `magpie daemon web` 的回环链接，并建立随机本地端口到远端 Web 端口的 c2s 转发。点击「在浏览器打开」链接，由本机管理服务调用默认浏览器访问官方页面，管理供应商和远端当前用户下的 Agent；也可复制地址手动访问。打开前会重新核实远端服务并获取有效链接；无法启动浏览器时页面会提示手动复制。保持 SSH 连接；断开后本地入口失效。

管理链接携带有权限修改远端配置、查看供应商密钥的 Web key，不要分享。它与模型调用使用的 gateway key 不同。链接只在显式请求后返回页面，不进入操作记录或本地 SSH 配置；自动对接本机供应商时也会在后台读取管理链接，通过其 Cookie 调用远端接口，密钥不会返回页面。切换连接和页面退出时清空显示。`magpie-web` 是此入口使用的临时转发标识，同名其他规则不会被覆盖。停止服务或卸载完成后，自动关闭本入口创建的转发、释放活跃通道并清除自动重连意图；SSH 与其他转发保持连接。检测环境确认服务已在外部停止或 Web 已禁用时也会清理此入口，页面同步清空旧地址。

默认 Gateway 模式会隐藏 Agent 页面；需要管理远端 Agent 时，在远端官方页面的通用设置关闭 Gateway 模式。Agent 指远端已安装或已配置的 CLI/桌面工具，各工具的字段和生效条件不同，并非通用远程任务或进程管理。

## 仅服务器本机访问

所有由插件启动的 `s2c / -R` 远程转发都必须绑定数字回环地址（如 `127.0.0.1` 或 `::1`），自动供应商对接使用 `127.0.0.1`。页面固定使用 `127.0.0.1`，后台也会拒绝全网地址、局域网地址和其他主机名。旧配置仍可读取，但对外监听的预设不能启动，需要先改为回环地址。

SSH 返回转发成功后，插件通过服务器的 `/proc/net/tcp`、`/proc/net/tcp6` 或 `ss` 核对该端口的全部实际监听，确认没有 IPv4 或 IPv6 对外监听后才接受转发流量。检查需要 POSIX shell 和 `awk`；读取 `/proc` 时还通过 `od` 确认字节序，工具不可用时尝试 `ss`。发现全网监听或无法核实时，关闭相关 SSH 会话并释放其转发；其他 SSH 连接保持独立。远端 SSH 需允许执行只读检查；`GatewayPorts` 应使用 `no` 或 `clientspecified`，`yes` 可能将请求的回环监听强制改成全网监听。入站转发也会拒绝非回环来源。

「启用 Web」将用户服务重建为网关 `127.0.0.1:3425`、Web `127.0.0.1:3430`。启动、重启以及更新或恢复后重新启动服务之前，都会检查用户服务的来源、显式回环网关与 Web 参数和 systemd 覆盖配置。没有明确设置 `MAGPIE_ADDR`、使用 `--lan`、公开地址、环境文件、drop-in 或无法识别的服务配置时拒绝启动。已有普通服务可通过「启用 Web」重建；存在自定义覆盖配置时需先在服务器核对，插件不会自动删除这些文件。

已有 Web 服务但回环范围未确认时，页面显示「重建回环配置」，按后端可用性开放预览和执行。已有服务已确认回环时仍显示已启用；自定义覆盖配置或其他不安全条件继续禁用重建。

服务启动后还会核对网关和 Web 端口的实际监听；发现对外监听或无法核实时停止本次启动的服务，并报告失败。停止、备份和卸载入口仍可用于处理旧服务。上述约束作用于插件发起的操作；服务器管理员后续直接修改服务或另行启动的实例，需要自行保持回环配置。

## 自动对接本机 Magpie

每次 SSH 连接成功（包括自动重连）后，插件默认自动检测本机 Magpie 的局域网共享网关和远端供应商；连接期间每 30 秒重新核对或重试。远端需已运行回环 HTTP Web 管理服务，本机需开启 Magpie 局域网共享并提供有效的共享网关密钥。不满足条件时显示等待或错误，远端任务正在执行或待核实时等待任务结束，不与安装、更新或恢复同时修改供应商。启用 Web 后可等待下一轮检测，或点击「局域网网关对接 → 重新检测对接」。

插件从本机 Magpie 配置读取共享开关、端口及共享网关密钥。宿主的 `MAGPIE_ADDR` 提供实际端口；即使它被宿主归一化为 `127.0.0.1`，目标也使用本机真实局域网网卡地址，不会回退到 localhost。优先使用家庭或办公网段，再考虑 CGNAT 和 IPv6 ULA；排除回环、全网、链路本地及代理 TUN 地址。明确指定的局域网 `MAGPIE_ADDR` 或 `MAGPIE_PUBLIC_URL` 需属于本机网卡。逐个核实候选入口返回 Magpie 信息且接受共享网关密钥，页面显示最终局域网目标。

插件随后通过已认证 SSH 会话读取远端路由与 `SSH_CONNECTION`，与本机实际网卡的 CIDR 或连续子网掩码比较，优先探测有同网段证据的入口。直连的决定条件是远端携带共享密钥访问实际网关端口成功，并核对返回的 Magpie 名称和版本。存在下一跳、两端子网不同、没有路由源地址或 SSH 经其他入口连接时，也会进行 HTTP 验证；缺少网段证据不会阻止请求。IPv4、IPv6 ULA 及多网卡分别检测；仅有相同私有地址前缀或能 ping 通仍不足以证明直连可用。

| 检测结果 | 供应商地址与访问路径 |
| --- | --- |
| 远端带密钥 HTTP 请求通过，包括跨网段路由互通 | `http://<本机局域网 IP>:<网关端口>`，模型请求直接访问局域网，无需 SSH 端口转发 |
| 网关不可达、鉴权失败或响应不匹配 | 远端回环端口 → SSH → 受认证的模型转接服务 → 本机 Magpie 局域网地址 |
| 远端缺少 curl 或网络探测不可用 | 保留 SSH 回退路径；页面显示不能确认直连的原因 |

例如，本机网关为 `http://192.168.1.115:3425`，服务器为 `10.10.10.81`，只要服务器能直接请求该网关并通过共享密钥验证，就使用局域网直连。远端 curl 请求禁止环境代理、用户 curlrc 和重定向；本机探测及模型转接也绕过环境 HTTP 代理。直连成功时，自动供应商管理同样经 SSH 标准输入执行受限 curl 请求访问远端回环 Web 接口，不创建管理端口转发。远端无 curl 时，自动配置兼容原回环 Web 转发；用户显式打开官方 Web 页面仍按原方式建立管理转发。

错误提示分别标明「验证本机局域网网关」「登录远端 Web 管理服务」「读取远端供应商列表」或「保存远端供应商」，并显示目标地址、端口及 HTTP 状态或 curl 退出码。curl 7 表示无法连接目标端口，28 表示请求超时；HTTP 401/403 表示认证或访问权限被拒绝，404 表示接口不存在。先根据提示判断失败目标是本机局域网网关还是远端 `127.0.0.1:<Web 端口>`。网关已验证但管理请求失败时会明确显示「本机局域网网关直连验证已通过」，并保留已有模型隧道，待供应商保存及回读成功后再清理。远端 Web 管理密钥用于登录管理页面，本机共享网关密钥用于模型网关；提示不包含登录查询参数、Cookie、响应正文或 curl 原始错误输出。

新建直连供应商名为「局域网 Magpie」，SSH 回退名为「局域网 Magpie（SSH）」。两种方式共用稳定标识，网络改变时更新同一供应商，保留名称、优先级等其他设置。切换前先保存待核实目标，写入后回读确认，再停止插件拥有的旧模型反向隧道；保存响应丢失时下一轮先读取列表核实。手动创建的同地址直连供应商或确实指向该局域网网关的反向转发可复用；其他手动转发不会被关闭。自动供应商地址或密钥被手动修改时停止自动覆盖；停用或清除密钥时保留设置。

直连供应商使用本机的局域网共享网关密钥，**该密钥会保存在远端 Magpie 的供应商配置中**；共享密钥轮换后自动更新远端供应商。SSH 模式使用独立通道凭据，本机转接服务将其换为共享密钥，只转发模型调用、模型列表及配额和用量读取；本机管理、密钥管理、插件和 MCP 管理接口不通过此通道开放，流式响应保持流式转发。SSH 模式共享密钥轮换只更新本机转接目标。两种方式的密钥均不返回本插件页面、不进入运行日志或本地对接状态文件。共享关闭或密钥不可用时停止转接，不使用 localhost。

SSH 断开会释放模型反向隧道；重新连接后重新检测网络，需要回退时复用已保存的远端端口。直连供应商配置在 SSH 断开后仍保留，局域网可达时模型请求可继续；页面显示「直连状态待检测」，自动核对需重新连接 SSH。对接记录保存在 `connections.json.provider-link.json`，version 2 记录服务器绑定、访问方式、地址、密钥后缀的 HMAC 校验值、可选反向端口及待核实切换；兼容读取 version 1 的旧隧道记录，成功同步后升级。独立 `connections.json.provider-link.json.key` 用于派生通道凭据和校验值，Unix 权限为 `0600`，需要保留且不进入连接备份。连接编辑器的自动对接默认开启，可按服务器关闭；关闭后停止插件自己的模型转发并保留远端供应商配置。

## 更新与备份

检测环境时只读执行当前程序的 `--help`，确认健康检查及用户服务命令，并从官方发布清单比较当前版本。仅确认存在较新版本时显示「更新 Magpie」；当前版本相同或更高时显示无需更新，版本无法识别或清单读取失败时显示待核实与重试入口，不影响其他服务操作。更新不依赖旧程序的在线更新命令；原服务正在运行时，仍需支持重启和健康检查。旧版如 `0.1.1327` 只要提供所需命令，也可更新或启用服务；缺少的具体命令会显示在对应按钮提示中。旧的环境缓存需要重新检测以取得版本和能力信息。

创建备份、更新前备份和恢复前备份统一使用远端 `tar` 保存 `config.tar.gz`，不调用官方加密备份命令，也不要求备份口令。**此归档未加密，可能包含供应商密钥和登录信息**，保存在权限为 `0700` 的本次操作目录。配置目录不存在时写入 `config.absent` 记录；配置存在但无法备份会拒绝继续。

更新与安装使用相同的本机下载和 SSH 上传流程，锁定预览时确认的版本，不调用需要远端联网的 `magpie update`。上传校验完成后，先创建配置归档并复制旧程序，再在原程序所在目录暂存新程序并替换；备份失败会阻止替换。原服务正在运行时才重启并检查健康状态；原停止状态不主动启动。「创建备份」仅保存配置和程序，不更新程序或重启服务。备份目录为 `${XDG_CONFIG_HOME:-$HOME/.config}/magpie-remote/backups/<操作 UUID>/`，包含相应配置备份、旧程序 `magpie` 和版本记录。请妥善管理归档，并按需转移备份；本插件不自动删除远端备份。

本机下载文件保存在独立临时目录，完成、失败或上传中断后清理；单个资产上限 512 MiB。下载失败、大小或哈希不符时不派发远端变更。下载完成后重新检测环境，程序或服务已变化时要求重新预览。SSH 上传使用流式传输，远端未通过完整文件的 SHA-256 校验时不会安装或覆盖程序。本机仍需能访问官方清单与下载源；此功能解决服务器无法联网下载的问题，不提供 Magpie 运行时所需的外部网络。

「远端备份」可读取本插件生成的备份，显示创建时间、版本、格式、大小与是否包含程序副本，并支持手动创建、恢复配置和删除。列表只读取元数据和校验值，不返回备份内容。创建和删除均先预览；删除仅处理本插件备份目录中的选定 UUID 条目，卸载程序后仍可清理备份。已存在的更新备份也会出现在列表，旧备份没有版本记录时显示未知。

配置归档和无配置目录快照支持自动恢复。先保存恢复前的配置归档与当前程序，在独立临时目录中校验并展开所选归档；确认可用后才停止原先运行的服务并替换配置目录。无配置目录快照会移除当前配置目录。替换失败时尝试还原原目录；恢复成功后仅重新启动原先运行的服务并检查健康状态，原停止状态保持停止。归档无效或包含越界路径时，在停止服务和替换配置之前拒绝执行。预览绑定选定条目的文件校验值，内容变化时拒绝执行。

恢复结果通过固定的 `MIGPIE_RESTORE_V1` 记录分别报告配置状态（`not_applied` / `applied` / `rolled_back` / `unknown`）、服务状态（`unchanged` / `running` / `stopped` / `unknown`）、回退状态（`not_needed` / `succeeded` / `failed`）和可选恢复目录。替换失败后搬回原配置成功不代表服务已恢复；搬回失败会保留临时目录的 `previous` 并报告其位置。配置已应用后若启动或健康检查失败，不自动回退，服务标为待核实，恢复依据指向操作前快照。`running` 仅在启动并通过健康检查后报告，原停止服务成功恢复时保持 `unchanged`。

恢复会替换整个配置目录，保留当前程序版本，配置目录以外的数据不会随归档恢复。旧程序副本不代表跨版本配置一定可以降级，页面不提供自动回退二进制。历史 `config.magpie` 加密备份仍显示在列表并可删除，需要使用原工具和原口令手动恢复；不完整备份不能自动恢复。

## 操作进度与断线

变更必须先读取预览，再提交其短时 revision。提交前复核连接配置、程序哈希与服务文件哈希。相同 revision 重复提交返回同一任务；同一连接同一时刻只执行一个变更。页面刷新不取消后台任务，也不会自动重发安装或更新。

远程页顶部的任务摘要分别显示「本机下载程序」和「上传程序到服务器」，以及备份、安装、重启与健康检查等阶段。页面约每 2 秒显示已下载或已上传大小与速度；官方清单提供文件大小时显示下载百分比，上传使用本机已校验文件的实际大小计算百分比。上传字节表示交给 SSH 通道的数据，最终完整性以远端校验结果为准。换阶段、完成、失败、结果未知或 SSH 断开后停止显示活动进度。字节只更新当前任务快照，阶段变化才写入运行日志。

远程操作的提交、执行、成功、失败和断线待核实事件写入当前连接的「运行日志」，与 SSH、转发事件一起过滤和查看，保留最近 200 条，宿主重启后清空。失败步骤、退出码、分类原因和已完成的备份位置合并到对应日志条目，不另设重复任务详情区；远程页面仅保留任务摘要与日志入口。原始命令输出和 Web 管理密钥不进入运行日志。

本地 `connections.json.remote.json` 保存最近环境、每个连接的当前任务和最多 20 条旧终态摘要，仍使用 version 1；旧文件没有历史字段时兼容读取。开始新任务时才归档旧终态，未知任务不能被轮换。历史可在「运行日志 → 远程任务历史」按全部、失败和待核实筛选，或用操作 ID 查询；历史轮换不删除服务器上的操作目录或备份。文件损坏、历史重复或非终态历史会明确报错，不覆盖旧内容。新任务先记录 `dispatch: pending`，下载并复核后在执行前持久化 `possible`；重启时 `pending` 的任务，包括尚在本机下载的任务，标为 `failed` / `REMOTE_NOT_DISPATCHED`，可重新预览。其他原运行任务，包括缺少派发字段的旧记录，均标为结果待核实。远端使用 `magpie-remote/operation.lock` 互斥，将状态写入 `magpie-remote/operations/<UUID>/state`，并在 `result` 中记录操作标识、失败步骤、退出码、可识别的错误类别与备份完成标记。只有固定字段返回页面，不保存命令的原始输出或口令。

SSH 断开、超时、通道没有明确退出码时，变更任务标为结果待核实。重新连接后点击「检测环境」，取得远端明确的完成记录且操作锁已释放时，恢复任务结果。不根据版本或服务看似正常就自动重试。关闭 SSH 通道不能保证远端进程一定终止。

如果检测后始终显示结果未知，可点击任务摘要旁的「解除待核实」。**先在服务器确认该任务及其子进程均已结束，并核对程序、配置与服务的实际状态**，再在弹窗中确认。后台会再次检测并优先采用新出现的完成记录；仍无结果时，仅清理旧任务的残留锁，将本地任务标为失败并保留历史，不重新执行安装或更新。重新检测后，未安装时可重新预览安装，已安装时使用现有安装。恢复请求超时或断线可再次解除，部署不会被重放。

新任务在锁内记录任务 UUID 和 Shell PID，并在收到 HUP、INT、TERM 或 PIPE 时尽量保存失败结果后释放锁；若下载子进程尚未结束，会先等待它结束。解除时遇到仍存在的 PID、其他任务的锁或目录中的未知文件会拒绝清理。恢复本身使用短时互斥锁，记录进程归属，异常退出后可在下次解除时清理已结束进程的残留锁。旧版操作锁没有进程归属信息，必须由用户核实进程及子进程已结束；不能仅凭页面显示断线判断可清锁。

核实中断任务时，可以通过独立 SSH 终端查看锁归属、任务记录与当前用户进程；将 `<操作 UUID>` 替换为页面显示的任务标识：

```sh
base="${XDG_CONFIG_HOME:-$HOME/.config}/magpie-remote"
cat "$base/operation.lock/owner"
cat "$base/operations/<操作 UUID>/state"
cat "$base/operations/<操作 UUID>/result"
ps -u "$(id -u)" -o pid,ppid,stat,args --forest
```

旧任务可能没有 `owner` 或 `result` 文件。核对任务 Shell 和它派生的 `curl`、`magpie update` 等进程均已结束后再确认解除；这些命令只查看状态。

有运行中或待核实任务时不能删除连接或恢复全局 SSH 配置。待核实任务允许更新同一服务器的 SSH 凭据以便重新连接，不能把这条连接改指向另一台服务器。

## 本机远程任务记录损坏时

`connections.json.remote.json` 损坏、不可读或记录不合法时，页面顶部显示「远程任务记录需要修复」，列出记录路径。普通 SSH 连接列表和日志仍可读取，也可新建连接、修改同一服务器的名称或认证配置；删除连接、改服务器地址/端口/用户名、全局恢复以及远程管理操作继续暂停，避免丢失尚未核实的任务。

展开提示并点击「保留原件并重新读取」，插件先将检测失败时读到的原始字节保存到 `connections.json.remote.json.recovery/<UUID>.json`，然后重新读取记录文件；同样的损坏内容不重复生成副本。保留失败时不会加载新状态。修复只应纠正格式或损坏字段，保留所有连接标识、服务器绑定、当前任务和历史，完成后再次点击该按钮，无需重载插件。

插件必须完整校验所有记录后才恢复管理，不采用部分加载结果，不自动使用旧快照或空文件替代。删除记录文件也不会解除本次损坏状态。可能已派发的运行任务重新加载后仍为待核实，需要连接并检测实际结果；重新读取不会执行安装、更新或其他远端变更。无法完整还原任务记录时，保留原件并在服务器核实任务，不能通过清空历史跳过保护。保留文件不自动轮换，确认不再需要后可自行归档。

## 更新失败时排查

页面显示失败步骤和退出码，并在识别到网络、权限、磁盘空间、交互要求或不支持的命令时给出相应提示。备份或旧程序复制失败会注明尚未执行更新；更新命令完成后若重启或健康检查失败，会提示先检查当前版本与服务，不要直接重复更新。配置和旧程序都已保存时，即使后续步骤失败，页面仍显示备份目录。

只显示“退出码 1”的旧任务无法还原具体原因，检测环境也不会自动重新执行它。先检查远端记录，可在服务器执行以下只读命令，将 `<操作 UUID>` 替换为页面的任务标识：

```sh
base="${XDG_CONFIG_HOME:-$HOME/.config}/magpie-remote"
cat "$base/operations/<操作 UUID>/state"
cat "$base/operations/<操作 UUID>/result"
ls -lh "$base/backups/<操作 UUID>/"
"$HOME/.local/bin/magpie" --version
systemctl --user is-active magpie.service
```

旧任务没有 `result` 文件时，文件不存在是预期现象。`config.magpie` 或 `config.tar.gz` 存在只能说明相应备份文件已生成；同时存在旧程序 `magpie` 才表示更新前的两步备份都已完成，仍不能证明更新成功。请勿直接分享备份文件，其中可能包含供应商密钥。旧版本任务显示「执行官方更新」及网络错误时，表示其远端原生更新命令下载失败。新任务从本机下载并上传，下载错误应检查本机网络、代理和临时目录；上传失联后先检测远端结果，避免重复提交。

## 卸载与支持边界

自动卸载只接受当前用户 `~/.local/bin/magpie` 的非符号链接普通文件，先通过官方命令移除已安装用户服务，再删除程序。保留供应商配置、登录信息与备份。卸载前通过官方页面恢复仍接入该网关的 Agent，插件不会自动改写各 Agent 配置。

首版不接管系统路径、包管理器安装、容器或 system 服务；不运行 sudo，不自动开启 linger。用户服务能否在退出 SSH 后持续运行取决于服务器的用户会话和 linger 设置。命令形式按 Magpie 0.1.1472 及 0.1.1476 官方资料核对，并以当前二进制的帮助信息确认所需命令。帮助未列出所需命令或参数时仅禁用相关操作；这不代表所有版本的运行行为均已实机验证。

预览与哈希复核可以发现部分并发变化，但不是与其他 Magpie 进程共享的事务锁。操作期间不要同时从另一个客户端修改同一安装。后台只调用固定操作，不提供任意 shell 工具。

## 页面内部操作

以下操作供管理页调用，不注册为 MCP 工具。

| 内部操作 | 参数 | 结果 |
| --- | --- | --- |
| `remote_status` | `connectionId`、可选 `refresh` | 缓存环境、当前任务与历史；`refresh: true` 连接后探测并核实未知任务 |
| `remote_preview` | `connectionId`、`action`；恢复或删除时加 `backupId` | `revision`、变更清单、提示、归档备份方式 |
| `remote_apply` | `connectionId`、`action`、预览的 `revision` | 立即返回后台任务，后续查询状态 |
| `remote_operation` | `connectionId`、可选 `operationId` 或 `history: true` | 最新任务或 `null`；按 ID 查当前/历史；历史模式返回 `{connectionId, limit: 20, operations}`，当前加旧终态最多 21 条 |
| `remote_recover` | `connectionId`、当前 `operationId`、`confirmed: true` | 用户核实任务及子进程结束后解除待核实状态；优先核实完成记录，否则清理残留锁并保留失败任务，不重放部署 |
| `remote_web` | `connectionId`、可选 `port` | 临时本地访问地址和带管理 key 的登录链接 |
| `remote_provider_sync` | `connectionId` | 检测本机网关和远端网络，优先验证局域网直连，否则使用 SSH；返回 `mode: "direct" / "ssh"`、供应商地址及不含凭据的状态 |
| `remote_backups` | `connectionId` | 此连接的远端备份元数据列表 |

`action` 为 `install`、`update`、`start`、`stop`、`restart`、`enable_web`、`backup`、`restore`、`delete_backup`、`uninstall`。`remote_status` 同时返回各 `actions` 的 `enabled`、禁用原因与代码，以及 `update.state`（`available` / `current` / `unknown`）、版本与检查时间；涉及备份的 `remote_preview` 返回 `backupMode: "archive"`。恢复的 `backupId` 绑定在预览中，提交无需再次传入。远程操作不接收备份口令或独立凭据字段。
